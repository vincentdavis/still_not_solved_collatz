Collatz  ·  3n+1  ·  an interactive note

Every cycle has a largest odd number. Which numbers can it be?

If the Collatz conjecture is false, some loop of numbers repeats forever. A finite loop has a biggest element — that isn't a conjecture, it's arithmetic. Being the biggest turns out to be a very demanding job, and most odd numbers can be shown, in one line each, that they can't do it.

Two independent constraints do the work. The maximum has to fall on the next step, because nothing in the loop is bigger than it. And it has to be reached from something smaller, because its predecessor is in the loop too. The first constraint is about powers of two; the second is about powers of three. Below, they're printed as two inks.

The two inks

Three ways to fail, in one line each

Work with the odd-to-odd map: from an odd n, form 3n+1 and strip every factor of two at once. Write S(n) = (3n+1)/2^b, where b counts the halvings.

Rule A — it goes up. If n ≡ 3 (mod 4) then 3n+1 ≡ 2 (mod 4), so there is exactly one halving, and S(n) = (3n+1)/2 > n. One halving never undoes a tripling. Such an n ascends, so it cannot be the maximum. Kills half of all odd numbers.
Rule B — nothing reaches it. If 3 | n, then n has no odd predecessor at all: 3y+1 = 2^b·n would force 1 ≡ 0 (mod 3). A number with no predecessor can't be in a loop. Kills a third.
Rule C — only bigger things reach it. If n ≡ 1 (mod 3), its odd predecessors are (4n−1)/3, (16n−1)/3, …, and all of them exceed n. To be the maximum it would need a predecessor at most itself. Kills another third.
The general lemma behind Rule C. Every odd p coprime to 3 has at most one odd predecessor below itself — never two, for any variant of the map. When p is a cycle maximum that predecessor is forced to be (2p−1)/3, with exactly one halving. There is nothing to search.
Overprint

Both inks at once: the wheel mod 36

Rule A is a statement mod 4. Rules B and C are statements mod 3. Combined by the Chinese remainder theorem, the maximum must satisfy M ≡ 5 (mod 12) — one odd number in six.

Then it recurses. The forced predecessor (2M−1)/3 is itself in the loop, so it too must escape Rule B. That is a condition mod 9, and it removes exactly one of the three surviving classes mod 36.

The network

Draw the predecessors and the rules become shapes

Turn the map around. Instead of asking where a number goes, ask what could have come before it. Every odd number has a set of odd predecessors — and the arithmetic mod 3 decides the shape of that set completely. The arrows still point the way the map runs, so the branches grow outward while the flow drains inward.

So the two rules stop being congruences and become properties of a picture. A cycle maximum needs an edge coming in from below, and it needs to fall on the way out. Nodes with no downhill edge are unreachable from beneath; nodes divisible by three are unreachable from anywhere at all.

Dead ends. If 3 | n the node has no children. Nothing in the whole graph maps to it. These are the pink terminals.
All uphill. If n ≡ 1 (mod 3) every child is larger than n. You can only arrive from above, so n can never be the biggest thing in a loop.
Exactly one downhill. If n ≡ 2 (mod 3) precisely one child is smaller — (2n−1)/3, the thick violet edge. Never two. That is the whole content of the predecessor lemma.

Zoom out and the same structure covers every odd number at once. Below is the entire predecessor network up to a bound, rooted at 1 — the tree every Collatz trajectory runs down. The ringed nodes are the only candidates for the largest element of a cycle, and there are strikingly few of them.

One step back

The walk backwards is forced, then it isn't

Start at a candidate maximum and walk backwards. The first hop has no freedom at all: exactly one halving. The second hop has its parity fixed by arithmetic mod 3 and its size capped at two halvings, which together pin it down uniquely.

That determinism is what makes the sieve cheap. It's also what runs out — by depth four the size bound stops biting, the walk starts to branch, and the sieve slows to a crawl.

Evidence

Testing it where cycles actually exist

Everything above is conditional on a cycle nobody has ever seen. That is a bad position to test from — a false claim about 3n+1 cycles is unfalsifiable if there aren't any.

So test it on 3n+q instead. For q = 5, 7, 11, … the same map has plenty of genuine cycles, and every statement here has a q-general form. If a derivation is wrong, these cycles find it. Two of mine were wrong; these cycles found them.

These cycles refuted two claims I made. I asserted that Rule A needed the hypothesis M > q — it doesn't, it holds unconditionally, and the two cycles I offered as counterexamples actually satisfy it. And I attributed the two-halving cap to a cycle-length condition L ≥ 3; the truth is a size bound, M > 11q/7. q = 37's cycle 53 → 49 → 23 has L = 3 and breaks it.
Working backwards from what we know

Every path back from 1 has the same closed form

There is one cycle nobody disputes: 1 → 4 → 2 → 1. It is worth asking what the paths leading into it look like, because they turn out to have an exact algebraic form — and because the form, applied to a path that closes on itself instead, is the cycle equation.

Take k odd-steps backwards from 1 with halving counts b₁,…,b_k, write B_i = b₁+…+b_i for the running totals and B for the whole sum. Then the number you land on is pinned exactly:

3k · n  =  2B  −  Σi=1..k 3i−1 · 2B−Bi
Böhm & Sontacchi, 1978 — verified here against direct iteration on 189 paths, 0 mismatches
The tree never merges. Distinct halving vectors always give distinct numbers — with the halving count capped at the twelve the buttons offer, and setting aside the one edge b = 2 that sends 1 back to itself, that is 5, 18, 72, 288, 1152, … paths at each depth and exactly that many distinct values. That is forced: going forward is a function, so every number has exactly one parent. The lone self-loop is the trivial cycle, and it is the only place in the picture where a path returns somewhere it has already been.

Why this cannot find a counterexample

Here is the catch, and it is structural rather than a matter of effort. Nothing inside a cycle ever reaches 1 — it cycles. So a hypothetical second cycle sits in a different connected component of the graph, and no reverse path from 1 can ever land on it. The two pictures below never touch.

And it is circular as a strategy. Collatz is true exactly when the reverse tree from 1 reaches every odd number. "Describe all reverse paths from 1" is the conjecture restated, not a reduction of it. The combined sieve at depth one leaves six classes mod 144 — 17, 29, 53, 65, 101, 125 — and every one of the 834 numbers below 20 000 in those classes turns out to reach 1.

Where the form does earn its keep. Apply the identical algebra to a path that closes on itself, y_k = y_0 = M, and the same identity becomes the cycle equation:

M · (2B − 3k)  =  Σi=1..k 3i−1 · 2ji
the trivial cycle is its smallest solution: k=1, B=2 gives 1·(4−3) = 1

So 1 → 4 → 2 → 1 is not merely an example of the form — it is the k = 1 root of it. The real question is which other (k, B, j₁…j_k) can satisfy the closed version, and that needs 2^B/3^k to sit implausibly close to 1. Which is the wall in the next section.

The ceiling

Why the sieve can't finish

It's tempting to think you just keep sieving. You don't. Both halves have measured limits, and neither goes to zero.

The powers-of-two half saturates: no matter how deep you push it, it never removes more than about of the odd numbers. The powers-of-three half keeps cutting, but slower than its modulus grows — by depth 20 you have spent 31.7 bits of modulus to buy 9.7 bits of sieve, and the number of surviving classes is increasing.

What actually stands between us and a proof is a different kind of statement. Going once around a cycle multiplies by 3 at each of L odd steps and divides by 2 a total of B times, so closing the loop needs 2^B / 3^L to sit extraordinarily close to 1 — an exceptional rational approximation to log₂3. That's the real obstruction, and this sieve never touches it.

The structural reason

The backward sieve isn't an approximation. It's the problem.

Both sieves look alike — pick a depth, cut some residues, repeat. But ask what happens to a number that is never eliminated, at any depth, and they come apart completely. One question is vacuous. The other is the Collatz conjecture.

How deep numbers actually survive

What is machine-checked

The substantive half of the equivalence is formalized in Lean 4, without Mathlib and without the axiom of choice.

And the reason congruences can never finish

Each sieve condition is a finite union of residue classes — a closed set in the profinite integers. A nested sequence of nonempty closed sets in a compact space always has nonempty intersection. So no matter how deep you push it, congruence conditions will always admit 2-adic and 3-adic solutions.

An adic solution is not an integer. Telling the two apart is precisely what congruences cannot do — and precisely why every real cycle bound in the literature routes through Baker's theorem on linear forms in logarithms, which this page never touches.

A negative result

One constant we could pin down, and one we could not

The death depth falls off geometrically, so the obvious next question is: at what rate? There is a natural candidate — the growth constant of the backward tree itself, divided by 3. Chasing it turned into a clean lesson about when a counting problem is tractable and when it isn't.

Two different counts are involved, and only one of them is easy.

The tail rate: two models, and a coin flip

Since each halving vector pins exactly one residue but a single M can carry several chains, a_k ≤ N_k — and the ratio decays. How it decays is the whole question: decay by a constant factor per step means a slower growth rate for a_k; decay by a power of k leaves the rate untouched.

Testing the belief itself

Check the heuristic where cycles actually exist

Everything on this page that says a cycle is unlikely rests on one heuristic: the expected number of bounded backward chains decays like (λ/3)^k. Subcritical — but by only 5.4%. The whole conjecture lives in that margin, and nobody can check the heuristic against a real counterexample, because none is known.

Except in 3n+q, where cycles are abundant. That is the one laboratory where the heuristic can be held against reality. So: does it predict how many cycles each q has?

Count primitive cycles — gcd(q, elements) = 1, so scaled copies of smaller systems aren't counted twice — with maximum below R·q. Fixing the ratio rather than the bound makes the prediction identical for every q, so the counts become comparable and the distribution testable.

What is doing it

The clue is where the excess sits. Over-dispersion is extreme within a single cycle length — variance-to-mean up to 13.9 at fixed L — while counts at different lengths are essentially uncorrelated. So it isn't that some q are globally rich. Something acts per (L, B). It is this:

q  divides  2B − 3L    that is    2B ≡ 3L (mod q)

The proof is three lines. For a prime p | q, the relation 2^{a_j}·x_j = 3x_{j−1} + q shows p divides every element or none; primitivity rules out "every", so gcd(x₀, q) = 1. The cycle equation x₀(2^B − 3^L) = qS then forces q | 2^B − 3^L.

The burst

The strongest case is when 2^B − 3^L equals q exactly. Then the cycle equation collapses to x₀ = S — and every admissible halving vector of that (L, B) yields an integer candidate. One hit can produce a burst of cycles at once.

qcyclesof which burstexact hit 2^B − 3^L = q

And that is exactly why q = 1 is different

Ask when q = 1 gets a burst: 2^B − 3^L = 1. For L ≥ 2 the number 3^L + 1 is 2 or 4 mod 8 — never a higher power of two — so 2^B ≤ 4. No deep theorem required.

The verdict — including on this experiment

What a machine can check

A cycle-length bound, with the hard part quarantined

Every published lower bound on the length of a Collatz cycle — Steiner, Simons–de Weger, Hercher — runs through Baker's theorem on linear forms in logarithms, which bounds how close 2^B / 3^L can get to 1. That is deep analytic number theory, and the Lean development here has no real numbers at all, let alone Baker.

So the Baker input is quarantined: stated as an explicit hypothesis, in whole numbers, sitting in plain sight in the theorem's own statement. Everything downstream of it is proved.

The part that would normally need analysis

The textbook derivation takes logarithms of 2^B = ∏ (3 + 1/x_j). With no ℝ available that route is closed — but the same content turns out to sit in two elementary statements about whole numbers, each a plain induction.

What it gives you

Read contrapositively: if every number below m has been checked to reach 1, any cycle must be at least this long. Try it — κ and c would come from a published irrationality measure for log₂3.

Not vacuous — checked on a cycle that exists

A formalization about a hypothetical object can be true purely because nothing satisfies its hypotheses. So the theorem is stated for 3n+q and instantiated on a real cycle: the q = 5 cycle that has appeared throughout this page.

Standing on the frontier

Re-running the record ladder at 2025's verification bound

The strongest published cycle results come from one pipeline — Hercher (2023), building on Simons–de Weger — and it consumes exactly the inputs the wall two sections down says any finishing argument must consume: the continued fraction of log₂3, the verified convergence bound X₀, and positivity (2^B > 3^L). The other end

A cycle has a smallest element too

Everything so far has been about the largest odd number. But a finite loop has a smallest one as well, and the same one-line arguments run at that end — giving an exact mirror image.

At the minimum m, the next step can't go down, so 2^b ≤ 3 + q/m. Once m > q that right-hand side is below 4, forcing b = 1: the minimum ascends by a single halving. Coming in, a predecessor must be at least m, which forces a ≥ 2. Precisely the reverse of the maximum.

That hypothesis is not decoration. Drop it and the argument collapses — q/m can be large, 2^b has room, and real cycles take it. For q = 1 it is free, since the only cycle with m = 1 is the trivial one; in 3n+q it has to be earned, and the maximum carries the matching hypothesis M > q.

Infinitely many at once

Certifying a whole residue class

Every test on this page so far settles one number at a time, so no finite amount of work covers a range. One property changes that: above a computable threshold, d(M) depends only on M mod 3^k.

The exact size test and the magnitude-free one differ only when 2^{B_j} > 3^j and M is small enough to squeak under c_j/(2^{B_j} − 3^j). Above the largest such M they agree — and c_j is largest when the early hops are smallest, which gives a closed form, so the threshold needs no search at all.

Working from the top down

Fix the largest element. What must the rest look like?

Suppose O is the biggest odd number in a cycle. That single assumption pins down a surprising amount about everything below it — how long the cycle can be, how the climb and the fall must be shaped, and even what fraction of its steps take a particular form.

The cycle can only use what O can reach

Every element lies at or below O, and every element is reached from another one. So the whole cycle sits inside R(O) — everything reachable backwards from O without ever going above it. That caps the length outright.

The climb is slow. The fall need not be.

Split the cycle at its two extremes. Going up from the minimum, each step multiplies by at most (3 + q/m)/2 — about 1.5 — so climbing from m to O takes at least 1.71·log₂(O/m) steps. Coming down there is no such limit: one large halving can undo many small climbs.

And at least 41.5% of the steps are single halvings

Write u for the number of steps taking exactly one halving. Since every other step takes at least two, B ≥ u + 2(L−u), so u ≥ 2L − B. That is exact and holds on every cycle in the census.

The answer underneath

Why none of this could ever have worked

Five separate routes on this page end at the same wall, and each ends by measuring some density that stubbornly fails to reach zero. Here is the same fact with no densities, no limits and no analysis at all — and with something the other arguments never had: an explicit witness.

The periodic points are the cycle equation

Run the backward map with a fixed halving pattern and ask for a fixed point. Telescoping gives exactly one, and it is a rational number:

y  =  cL / (2B − 3L)

So the periodic points of the backward map are the candidate cycles — one for every halving pattern — and a genuine cycle is simply one that happens to land on a positive integer. Try a pattern:

The witness

Take the pattern where every hop is a single halving. Then 3y = 2y − 1, so y = −1 — at every length. And in the 3-adic integers −1 is …2222: every digit of its base-3 expansion is a 2, so −1 ≡ 3^k − 1 (mod 3^k) ends in a 2 at every depth — exactly the residue an odd halving count requires at every step. The class of −1 is therefore never sieved out.

And so

A congruence sieve tests membership in ℤ₃. It cannot see sign. It cannot see integrality. Its limit set is full of points like −1 and 1/5 that pass every congruence test at every depth and are not natural numbers.

It also explains the shape of every measurement above, in a single number.

The wall, sharpened

The sieve cannot even see q

The witness −1 says the sieve never empties. This says something stronger: every statistic the sieve produces is identical across all the 3n+q systems — including ones that really do have cycles.

Sk(q)  =  q · Sk(1)  (mod 3k)   ⟹   ak(q) = ak(1)

The proof is ten lines: the chain constant is linear in q (c_t = 2^{b_t}c_{t−1} + 3^{t−1}q with c₀ = 0, so c_t(q) = q·c_t(1)), the size caps 2^{B_t} ≤ 3^t never mention q, and multiplying by the unit q just permutes the residues mod 3^k. The forward 2-adic sieve scales the same way, so its 1.80-bit ceiling is q-blind too.
